# ExMail — передача проекта (handoff)

Актуально на 2026-11-09, версия **1.0.3** (тег `v1.0.3`, versionCode 4), пакет `io.github.denhaiz.exmail`,
репозиторий https://github.com/DenHaIz/ExMail.
Документ для разработчика или новой сессии, которые продолжат работу.

## 1. Статус

Android-клиент Microsoft Exchange (EWS): почта, календарь, контакты. Собирается (debug и release с R8),
73 unit-теста проходят (+1 интеграционный, пропускается без учётных данных), lint без ошибок. Используется на телефонах с корпоративным
Exchange; доработки по отзывам пользователей описаны в разделах 1a–2c.

**Данные организации в репозиторий не попадают** (требование администратора, 2026-11-06). Адрес сервера и домен почты
по умолчанию — только в локальном `company.properties` (в `.gitignore`, образец — `company.properties.example`); без него
сервер находится по рабочему e-mail при входе (раздел 4a). Сведения об организации для разработки — в локальной папке
`private/` (в `.gitignore`). В тестах и документах — только `example.com` и вымышленные имена. Выпуски для GitHub
собираются **без** `company.properties`.

История перезапущена 2026-11-06: прежние выпуски и коммиты удалены с GitHub, пакет переименован (прежнее название
содержало домен организации) — 1.0 ставится как новое приложение: старое удалить, войти заново. Дальше каждая версия
ставится поверх предыдущей (versionCode растёт, ключ подписи один) и приходит через обновление в приложении (раздел 1c).
Разделы 1d–2c — этапы разработки до перезапуска (их номера версий к нынешним не относятся).

Гонки «Остановить»/повтор, повтор при повороте экрана, повтор из «Недавних», лишние запросы к GitHub при фоновых запусках процесса |

| Почта | «Дыра» в списке, если новых писем больше страницы; одновременные обновления папки (новое письмо могло пропасть); бесконечная подгрузка при одинаковом времени писем; повторы в поиске по тексту и дате; поиск обновляется после пометки/удаления; «Отменить» работает, пока снэкбар на экране; удаление не прерывается при закрытии экрана; черновик, который не загрузился, нельзя сохранить или отправить (затёр бы его); встроенные картинки `cid:image1`/`image10`; длинные имена файлов; подгрузка в конце списка после ошибки |
| Уведомления, доставка | Быстрые обрывы подписки (прокси) — с паузой, а не бесконечный цикл; запуск службы, запрещённый Android 12+, не роняет приложение; уведомления можно включить после запрета (открываются настройки Android); «Мгновенная доставка» недоступна с объяснением, пока выключены «Новые письма» |
| Календарь, контакты, настройки | Падения: адресная книга с одинаковыми адресами, контакт без e-mail. Встреча из карточки контакта больше не «возвращается» во вкладке «Контакты». Закрытие формы встречи с изменениями — с вопросом, во время сохранения — нельзя; конец раньше начала — сообщение (было: встреча на 23 часа). Переговорная без данных о занятости — «нет данных», а не «свободна». Автоответ: «только контактам», отдельный текст для внешних и время из Outlook сохраняются; даты в настройках — «3 окт» |
| Навигация, вёрстка | Двойное нажатие не открывает экран дважды; «назад» во время анимации не срабатывает дважды и не опустошает вкладку; крупный шрифт (время в календаре, поле поиска, инициалы); цвета «принято/под вопросом/свободна» в тёмной теме; TalkBack: строки писем открываются и вызывают меню; получатель удаляется только крестиком; «Напоминание в момент начала» |

Не исправлено (в «Известных ограничениях»): тело черновика при сохранении — простой текст; вложения целиком в памяти;
старые страницы списка не сверяются с сервером; данные формы встречи при выгрузке приложения; виды календаря на
маленьких экранах с крупным шрифтом.

## 1c. Обновление из приложения

| Пожелание | Сделано |
|---|---|
| Обновляться по кнопке, без сайта | Настройки → «Обновления» → «Обновление приложения»: установленная версия, проверка, загрузка с ходом в процентах и установка. Диалог новой версии показывает описание выпуска и размер; «Обновить» загружает APK и сразу открывает установщик Android. При первом обновлении Android один раз спрашивает разрешение «Установка неизвестных приложений» для ExMail — после него установка продолжается сама. Строка «Версия приложения» перенесена сюда |
| Уведомление о новой версии | Проверка при открытии приложения (если прошлая — больше 6 ч назад) и раз в 12 часов в фоне (WorkManager, при наличии сети). При открытии — окно; в фоне — уведомление не чаще раза в 3 дня (канал «Обновления приложения»), нажатие открывает настройки с окном обновления. «Позже» — окно и уведомления через 3 дня. Уведомления выключаются переключателем «Сообщать о новых версиях» |

Как устроено (`update/AppUpdater`, `sync/Sync.kt` — `UpdateChecker`, `UpdateWorker`):
1. `GET https://api.github.com/repos/DenHaIz/ExMail/releases/latest` (без входа, лимит GitHub — 60 запросов в час с адреса;
   на 403/429 — «Слишком много проверок подряд»). Берётся первый файл `*.apk` выпуска, описание (`body`) и размер.
2. Обновление есть, если тег последнего выпуска (без «v») не равен `versionName`. Номера версий не сравниваются
   (их вид менялся: «1.01» вышла раньше «1.0.2»). Защита от отката — после загрузки: `getPackageArchiveInfo` — пакет `io.github.denhaiz.exmail`
   и versionCode больше установленного, иначе файл удаляется с понятной ошибкой.
3. Загрузка — отдельным OkHttp-клиентом (без NTLM и учётных данных почты, без переадресаций на HTTP), в
   `cacheDir/updates` через `.part`. Источники по очереди (`downloadUrls`): API GitHub (`…/releases/assets/<id>`,
   `Accept: application/octet-stream` — работает там, где не открывается github.com), зеркало jsDelivr
   `https://cdn.jsdelivr.net/gh/DenHaIz/ExMail@apk-v<версия>/ExMail.apk`, ссылка выпуска. «Остановить» закрывает
   соединение сразу. Старые загрузки удаляются при запуске приложения.
4. Установка — `ACTION_VIEW` с `content://` из FileProvider (`<cache-path name="updates">`), разрешение
   `REQUEST_INSTALL_PACKAGES`. Запускает её только `UpdateInstallHost` (в AppNav) — из Activity и когда приложение на
   экране (из фона Android установщик не покажет); флаг «установить после загрузки» — в `AppUpdater.installRequested`.
   Подпись проверяет сам Android: обновление ставится, только если APK подписан тем же ключом.

**Как выпускать следующие версии:** поднять `versionCode` и `versionName` в `app/build.gradle.kts`, собрать
`assembleRelease` тем же ключом (без `company.properties`), создать тег-зеркало `apk-v<versionName>` — отдельный
коммит без родителей с одним файлом `ExMail.apk` (`git hash-object -w` → `git mktree` → `git commit-tree` → `git tag`,
отправить тег), затем выпуск `v<versionName>` с APK, пометить Latest. Проверить: `curl -sL https://cdn.jsdelivr.net/gh/DenHaIz/ExMail@apk-v<версия>/ExMail.apk`
отдаёт тот же файл. В Windows ввод для `git mktree` — без символа CR (из Python — байтами): иначе имя файла станет
«ExMail.apk» с CR на конце, а jsDelivr надолго запомнит тег без файла (так вышло с `apk-v1.0.2`; зеркало этой версии не
используется — оно нужно только для обновления с неё на следующую). Описание выпуска (Markdown:
`**жирный**`, списки `- `) показывается в диалоге обновления без разметки; строка «Подробности…» опускается.

## 1d. Жесты в списке, поиск по дате (до перезапуска)

| Пожелание | Сделано |
|---|---|
| Выбор жестов во вкладке «Почта» | Настройки → «Жесты в списке писем»: «Свайп вправо» и «Свайп влево» — ничего, прочитано/непрочитано, флажок, ответить, переслать, переместить в папку, удалить. По умолчанию как раньше: вправо — прочитано/непрочитано, влево — ничего. Порог — середина строки для всех действий; фон показывает действие, после порога становится цветным (удаление — красным), строка при удалении уезжает за край, «Отменить» в снэкбаре как при удалении из меню. В «Черновиках» ответ и пересылка свайпом выключены (`SwipeRow`, `MessageActions.swipeRight/Left`, `SwipeAction`) |
| Поиск по дате письма | Под строкой поиска — фильтр «Любая дата»: сегодня, вчера, последние 7 / 30 дней, «Выбрать день…», «Выбрать период…» (календарь Material, будущие дни недоступны). Ищется по дате, по тексту или по обоим (`MailListViewModel.onSearchDates`, `SearchDateFilter`) |
| Выход из поиска жестом «назад» | Системная кнопка или жест «назад» закрывают поиск, а не уходят со вкладки (`BackHandler`) |
| Настройки — в шапке шторки | Значок-шестерёнка справа вверху боковой панели, рядом с ФИО; пункт «Настройки» внизу панели убран |

Поиск по дате на сервере: без текста — `FindItem` с `Restriction` (`IsGreaterThanOrEqualTo` / `IsLessThan` по
`DateTimeReceived` внутри `And`). С текстом — `QueryString` (AQS) без ограничения: сочетание `QueryString` и `Restriction`
на рабочем сервере не проверено, поэтому найденное отбирается по дате в приложении — страницами по 100 от новых к старым,
до 100 писем, просмотр не дальше 1000 (`MailRepository.inPeriod`).

Проверка оптимизации: строка списка без свайпов не создаёт состояние свайпа; фон свайпа рисуется только во время свайпа;
восстановление строки после удаления запускает корутину только у такой строки; настройки свайпов — отдельный поток
(`distinctUntilChanged`), строки перерисовываются только при их смене; отменённый поиск не гасит индикатор нового.

## 1e. Тёмные письма, жесты окна письма (до перезапуска)

| Замечание | Причина | Исправление |
|---|---|---|
| Чёрные прямоугольники вместо части письма в тёмной теме | `invert(1)` делал белый фон блоков письма (`background:white` в шаблонах Outlook и порталов) чисто чёрным, а фон приложения тёмно-серый (#111418) — блоки и выделения строк выглядели чёрными заплатками | Инверсия неполная: `invert(p)`, где p = 1 − яркость фона темы, — белый письма становится ровно серым фоном страницы (`invertAmount`, `pageColor`). Тело письма закрашено белым до перекраски, фон страницы — тот же серый. Цвета текста и ссылок пересчитаны под `invert(p)` (`forDarken(p)`), картинки возвращаются в исходные цвета точным обращением `invert(1) contrast(1/(2p−1))` (`MailStyleTest`) |
| Случайное «непрочитано» при прокрутке списка | Material засчитывал свайп по скорости: короткий быстрый взмах на 30 % строки | Срабатывает, только если строку дотянули до середины (проверка смещения в `confirmValueChange`); после середины фон становится цветным и телефон слегка вибрирует (`ReadSwipeRow`) |
| Меню по удержанию — долго | — | `HOLD_MILLIS = 500` |
| Окно письма: удобство и жесты | — | Свайп влево/вправо — следующее (более старое) / предыдущее письмо папки, с анимацией перелистывания; не мешает прокрутке и широким письмам, которые прокручиваются вбок. Щипок двумя пальцами — размер текста (подсказка «Текст N %», запоминается). При прокрутке тема письма появляется в верхней панели; заголовок компактнее |

Найдено и исправлено при отдельной проверке окна письма:
- письмо с фоновой картинкой на `<body>` всё равно становилось чёрным прямоугольником (правило «вернуть исходные цвета» срабатывало на сам body);
- картинки внутри `<picture>` или ячейки с фоновой картинкой показывались негативом (двойное обращение); фон `background:url(…)` не возвращался в исходные цвета;
- ползунок «Размер текста» перехватывался перелистыванием; выделение текста с протяжкой вбок листало письмо; диагональная прокрутка могла смениться перелистыванием;
- письмо из поиска листало всю папку — теперь свайп работает только для писем, открытых из списка папки;
- повторный щипок сразу после первого начинался со старого размера; письмо из уведомления поверх письма открывалось анимацией перелистывания;
- тема в верхней панели появлялась, пока длинный заголовок ещё виден.

## 2. Скорость, кэш, анимации (до перезапуска)

Главное — скорость и плавность.

| Замечание | Причина | Исправление |
|---|---|---|
| Список писем прокручивается с рывками | Выпускались debug-сборки (без оптимизаций, отладочный режим ART и Compose); в каждой строке шла анимация цвета фона под свайп; кнопка «Написать» пересчитывалась на каждом кадре и дёргалась; инициалы аватара — компиляция регулярного выражения на каждую перерисовку | Release-сборка: R8 и профиль компиляции (`baseline-prof.txt` + `profileinstaller`), код приложения и Compose компилируются заранее при установке. Фон свайпа рисуется только во время свайпа; «Написать» сворачивается после 24 dp прокрутки в одну сторону (`isScrollingUp` через `snapshotFlow`); время, цвет и инициалы в строке считаются один раз; фото сотрудников читаются с диска без очереди к серверу, «фото нет» запоминается на 7 дней |
| Картинки в письме — 1–2 с ожидания при каждом открытии | Встроенные (cid:) картинки скачивались заново при каждом открытии, подставлялись в HTML как base64, страница загружалась дважды; отметка «прочитано» задерживала показ | Дисковый кэш на **14 дней** (`data/MailCache`): письма целиком (полученное письмо не меняется) и встроенные картинки; картинки из интернета — HTTP-кэш OkHttp на 14 дней (150 МБ). WebView запрашивает картинки у приложения (`MailImages`, `shouldInterceptRequest`): текст виден сразу, картинки — по мере загрузки, из кэша — мгновенно; недостающие картинки письма скачиваются одним-двумя запросами. Отметка «прочитано» уходит в фоне. Движок WebView загружается заранее, пока приложение простаивает |

## 4. Ключевые решения

- **EWS + NTLM, не ActiveSync.** EWS на сервере принимает только `Negotiate/NTLM`; API богаче (free/busy, переговорные, автоответ).
- **Собственный NTLMv2** (`auth/`) с MIC и Channel Binding — работает и при Extended Protection.
- **HTTP/1.1 и один поток запросов** (мьютекс в `EwsClient`): NTLM аутентифицирует TCP-соединение. Фото — отдельный клиент
  `@SecondaryClient`, подписка на новые письма — `@PushClient` (держит соединение до 30 минут). Перед крупным запросом на
  «остывшем» соединении — короткий запрос для NTLM-рукопожатия, чтобы вложение не уходило трижды.
- **DOM (`javax.xml`)** — одинаково на Android и в JVM-тестах; большие вложения целиком в памяти.
- **FindItem** вместо SyncFolderItems: первая страница — обновление (сверка удалений по её окну), «загрузить ещё» — письма
  не позже самого старого в списке (`Restriction IsLessThanOrEqualTo DateTimeReceived`), без смещений.
- **Локальные изменения важнее устаревших ответов сервера** (`MailRepository.edits`): изменение «прочитано»/флажка/удаление
  и «прочитать всё» помечаются временем; ответ `FindItem`, запрошенный раньше, для этих писем не применяется. Отметки живут 10 минут.
- **Мгновенная доставка — EWS streaming + служба переднего плана**, без Google FCM (у сервера нет push-шлюза).
  Служба переднего плана сохраняет доступ к сети в режиме сна; входящие данные будят телефон. Тип `specialUse`
  (не `dataSync`: у того в Android 15 лимит 6 ч в сутки). Опрос раз в минуту при открытом приложении и WorkManager
  15–180 мин — резерв. Запрос «без ограничений в фоне» (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) не допускается
  правилами Google Play — приложение распространяется не через Play.
- **Часовой пояс**: TimeZoneContext с поясом Windows; если сервер его не знает — переход в UTC до перезапуска.
- **ChangeKey для ReferenceItemId всегда свежий** (`withChangeKey`): лишний `GetItem` дешевле ошибки сервера.
- **Тёмные письма — CSS-фильтр, а не algorithmic darkening WebView**: работает одинаково на всех версиях Android и WebView.
  Инверсия неполная (`invert(p)`), чтобы белый письма совпадал с фоном страницы; письма, которые плохо выглядят
  перекрашенными, открываются «в исходных цветах» из меню.
- **Жесты окна письма** (`messageGestures`) читают касания раньше WebView и прокрутки (проход `Initial`) и забирают их,
  только когда жест распознан: горизонтальный сдвиг вдвое больше вертикального — перелистывание, два пальца — щипок.
  Соседние письма — по дате в той же папке (`MessageDao.newerThan/olderThan`); соседнее письмо заменяет текущее в стеке.
- **Свайпы в списке настраиваются** (`AppSettings.swipeRight/swipeLeft`, ключи `swipe_right` / `swipe_left`),
  действие засчитывается по пройденному расстоянию (середина строки), а не по скорости.
- **Поиск по тексту и дате** — `QueryString` и отбор по дате в приложении (см. раздел 1d), без текста — `Restriction`.
- **Черновики:** новое — `CreateItem SaveOnly`; редактирование — `UpdateItem` + `CreateAttachment` + `SendItem`.
- **Повторение встреч** — только для новой встречи или одиночного события; удаление серии через `RecurringMasterItemId`.
- **Порядок боковой панели** хранится локально в DataStore.
- **Кэш писем и картинок — по настройке, по умолчанию 14 дней** (`MailCache`, `cacheDir/messages`, `mail-images`, `mail-web`;
  0 — не хранить): полученное письмо
  не меняется, поэтому повторное открытие — без запросов; «прочитано» и флажок берутся из списка. Черновики не кэшируются.
  Старые записи удаляются при запуске, всё — при выходе. Встроенные картинки — по адресу `https://inline.exmail.invalid/<id>`,
  который перехватывает приложение; если картинки из интернета не разрешены, все внешние запросы страницы получают пустую картинку.
- **Release со старым ключом**: 1.0 собрана release-сборкой (R8, `-dontobfuscate` — понятные стеки ошибок), но подписана тем же
  debug-ключом из `.toolchain`, что и тестовые версии, — ставится поверх без удаления. Если есть `keystore.properties`, используется он.
- **Анимации**: при переходах предыдущий экран остаётся под новым (`ExitTransition.KeepUntilTransitionsFinished`), закрываемый —
  поверх (NavHost рисует его выше); нижняя панель — поверх экранов, экраны вкладок резервируют под неё место.
- **Обновление через GitHub Releases**, а не Google Play: приложение распространяется APK; установка — системным
  установщиком (без тихой установки — Android всегда показывает подтверждение).
- **Информационная безопасность** (проверено 2026-11-09):
  - соединения — только HTTPS с системными корневыми сертификатами, без исключений (`network_security_config.xml`);
    переадресации EWS не выполняются (учётные данные не уходят на другой адрес);
  - пароль — AES-256-GCM ключом Android Keystore; на экране входа не сохраняется в состоянии экрана; в журналы ничего
    не пишется; резервное копирование выключено;
  - WebView письма: JavaScript, доступ к файлам и content:// выключены; ссылки открываются только по касанию и только
    `http`, `https`, `mailto`, `tel` (не `intent:`, `content:`, `file:`); картинки из интернета — по настройке;
  - поиск сервера: адресам-догадкам — только запрос без учётных данных; Autodiscover — только NTLM, на адреса домена
    из e-mail; неверный пароль прекращает перебор;
  - обновление: только HTTPS, файл проверяется (пакет, versionCode), подпись проверяет Android;
  - открыта только стартовая активность; служба, приёмник и FileProvider закрыты; FileProvider — только папки кэша;
  - остаточные риски: письма и кэш на телефоне не зашифрованы отдельно (защита — шифрование Android и блокировка
    экрана); выпуски подписаны ключом из `.toolchain` со стандартным паролем — файл ключа нельзя выкладывать
    (лучше свой ключ со стойким паролем, см. раздел 7).
- **Учётные данные:** пароль шифруется AES-256-GCM ключом Android Keystore; резервное копирование отключено.

## 4a. Подключение к серверу

Протокол — **EWS (Exchange Web Services)**: SOAP-запросы (XML) по HTTPS на один адрес сервера. ActiveSync, IMAP и OAuth не используются.

**По умолчанию**

1. Адрес: из `company.properties` (`ewsUrl` → `BuildConfig.DEFAULT_EWS_URL`). В сборке без него (выпуски на GitHub)
   сервер ищется по e-mail (`AccountRepository.findServers`):
   - типовые адреса домена — `exchange.`, `mail.`, `owa.`, `webmail.`, `outlook.`, `ex.`, `autodiscover.` и сам домен + `/EWS/Exchange.asmx`;
     подходят только ответившие `401` с NTLM или Negotiate (адрес, просящий лишь Basic, — обычный сайт с паролем);
     подключение к одному IP — 4 с, на проверку — 20 с; ничего не ответило — второй проход
     (`serverCandidates`); каждому параллельно уходит запрос **без учётных данных** (`EwsClient.isEwsEndpoint`,
     таймаут 6 с): подходит адрес, ответивший `401` с `WWW-Authenticate: NTLM | Negotiate | Basic`;
   - ответил только узел `autodiscover.` или ничего — Autodiscover POX с введёнными данными (см. «Другие варианты»),
     ответ может переадресовать на другой адрес почты (`redirectAddr`) или URL (`redirectUrl`, только HTTPS), до двух раз;
   - порядок попыток (`orderServers`): найденные по типовым именам, адрес из Autodiscover, затем EWS на узле
     `autodiscover.` — тот же сервер Exchange обычно отвечает и по этому имени. Так вход находится, даже если домен
     почты отличается от имени сервера, а ответ Autodiscover не получен;
   - вход пробуется по найденным адресам по порядку, на каждом — повтор при сбое связи и 502–504; неверный пароль
     прекращает перебор (не блокировать учётную запись); весь вход — не дольше 150 с; Basic — только с указанным адресом.
   Найденный адрес сохраняется в учётной записи, повторно не ищется.
2. Логин: рабочий e-mail или `ДОМЕН\логин` (с адресом сервера); короткий `ivanov` → `ivanov@домен`, только если в
   `company.properties` задан `mailDomain` (`AccountRepository.normalizeLogin`).
3. Проверка подлинности — **NTLMv2** собственной реализации (`auth/NtlmEngine`, `NtlmAuthenticator` для OkHttp):
   обмен Type1 → Type2 (вызов сервера) → Type3 с MIC и привязкой к TLS-каналу (Channel Binding), поэтому вход работает
   и при Extended Protection. Многие серверы принимают для EWS только `Negotiate/NTLM`.
4. Проверка входа: `ResolveNames` по логину (точное совпадение адреса) → имя и основной адрес; затем загрузка папок.
5. Пароль — AES-256-GCM ключом Android Keystore (`AccountStore`), резервное копирование приложения отключено.
6. Только HTTPS и системные корневые сертификаты (`network_security_config.xml`, HTTP запрещён).
7. HTTP/1.1 с keep-alive: NTLM подтверждает всё TCP-соединение, поэтому запросы одного клиента идут по очереди
   (мьютекс в `EwsClient`). Перед запросом больше 64 КБ на соединении, простаивавшем дольше 20 с, — короткий
   `GetFolder` («прогрев»), чтобы рукопожатие не отправляло вложение трижды.
8. С каждым запросом — `TimeZoneContext` с поясом телефона в формате Windows (`WindowsZones`); если сервер его не знает —
   работа в UTC (`EwsClient.activeTimeZone`).
9. При входе, выходе и поиске сервера открытые соединения сбрасываются (`evictConnections`): прежняя NTLM-сессия
   не используется для другой учётной записи.

**Три клиента** (`di/AppModule`), чтобы долгие запросы не мешали друг другу:

| Клиент | Назначение |
|---|---|
| основной `EwsClient` | почта, календарь, контакты, отправка |
| `@SecondaryClient` | фото сотрудников (`GetUserPhoto`) |
| `@PushClient` | подписка на новые письма: таймаут чтения 40 мин, заголовки `X-AnchorMailbox` и `X-PreferServerAffinity` (если серверов несколько, запросы попадают на сервер ящика) |

**Новые письма**

1. Мгновенно: служба переднего плана `PushService` («Почта на связи») — `Subscribe` (StreamingSubscriptionRequest на
   «Входящие») и `GetStreamingEvents` (до 29 минут, затем переподключение; при обрыве — пауза 5 с…5 мин, при появлении
   сети — сразу; при ошибке входа — раз в 30 минут, чтобы не заблокировать учётную запись).
2. Пока приложение на экране — проверка «Входящих» раз в минуту.
3. Резерв — WorkManager раз в 15–180 минут (настройка «Резервная проверка»).

**Другие варианты** — экран входа, «Дополнительные настройки» (свёрнуты):

- свой адрес EWS;
- «Найти по e-mail» — тот же поиск, что при входе (типовые адреса, затем Autodiscover POX: `https://домен/autodiscover/autodiscover.xml`, затем
  `https://autodiscover.домен/autodiscover/autodiscover.xml` с введёнными логином и паролем; берётся внешний адрес (`EXPR`),
  иначе внутренний (`EXCH`));
- домен (вход как `ДОМЕН\логин`) и e-mail, если он отличается от логина;
- способ проверки подлинности: **NTLM** (по умолчанию) или **Basic** — только по HTTPS (по HTTP не отправляется),
  логин `ДОМЕН\логин`; отправляется один раз в ответ на `401` с `WWW-Authenticate: Basic` (повторный `401` — неверный
  пароль). Способ хранится в DataStore (`auth`: `ntlm` | `basic`).

Не поддерживаются: Kerberos, OAuth (Microsoft 365), сертификаты клиента, ActiveSync, IMAP.

## 8. Известные ограничения

- Не реализованы: задачи и заметки, общие ящики и календари, делегирование, категории, пересылка вложением,
  несколько учётных записей, S/MIME.
- Тело черновика и описание встречи при редактировании становятся простым текстом (форматирование и встроенные картинки
  черновика из Outlook теряются).
- Старые страницы списка писем (за первой) не сверяются с сервером: удалённое в Outlook остаётся до выхода из учётной записи.
- Форма встречи не переживает выгрузку приложения системой (текст письма — переживает).
- Вложения отправляются base64 одним запросом (всё вложение в памяти, несколько копий; при нехватке памяти — сообщение).
  Вложенные письма (ItemAttachment) не открываются.
- Восстановление набранного письма после выгрузки приложения: текст, тема, получатели; выбранные файлы нужно добавить заново.
- Если сервер не знает пояс телефона, приложение работает в UTC: повторяющиеся встречи создаются в UTC
  (при переходе на летнее время в других странах время повторений может сместиться на час).
- Мгновенная доставка следит только за «Входящими»; на некоторых прошивках (Xiaomi, Huawei, Samsung «Спящие приложения»)
  нужно вручную разрешить автозапуск и работу в фоне. Удаление серии локально убирает события по теме до обновления.
- Room без миграций (`fallbackToDestructiveMigration`) — кэш пересоздаётся при смене схемы.
- Все выпуски подписаны отладочным ключом из `.toolchain/android-user-home/debug.keystore` (обновление поверх работает).
  Переход на рабочий ключ потребует удалить приложение один раз (и обновление из приложения на этот переход не сработает).
- Обновление из приложения требует публичного репозитория (GitHub API без входа): пока репозиторий приватный,
  приложение сообщает, что обновлений нет. Прежние установки (старое название пакета) на 1.0 не обновятся — только переустановка.
